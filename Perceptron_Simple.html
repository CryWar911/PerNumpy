class Perceptron:
    def __init__(self, input_size, learning_rate=0.1, epochs=100, random_init=False, seed=None, verbose=True):
        self.lr = learning_rate
        self.epochs = epochs
        self.verbose = verbose
        # Inicialización de pesos y sesgo: ceros (por defecto) o valores aleatorios pequeños
        if random_init:
            rng = np.random.default_rng(seed)
            self.weights = rng.uniform(-0.5, 0.5, input_size)
            self.bias = float(rng.uniform(-0.5, 0.5))
        else:
            self.weights = np.zeros(input_size)
            self.bias = 0.0
        self.errors_history = []
        self.converged_epoch = None

    def activation_function(self, z):
        # Función escalón de Heaviside (acepta escalares o vectores)
        return np.where(z >= 0, 1, 0)

    def net_input(self, X):
        return np.dot(X, self.weights) + self.bias

    def predict(self, X):
        """Predice una muestra (vector) o varias a la vez (matriz)."""
        return self.activation_function(self.net_input(X))

    def fit(self, X, y):
        """Entrena el perceptrón actualizando pesos y bias según la regla de aprendizaje."""
        X = np.asarray(X, dtype=float)
        y = np.asarray(y)
        for epoch in range(self.epochs):
            total_errors = 0
            for xi, target in zip(X, y):
                prediction = self.predict(xi)
                error = target - prediction
                # Actualización de pesos y sesgo
                if error != 0:
                    self.weights += self.lr * error * xi
                    self.bias += self.lr * error
                    total_errors += 1
            self.errors_history.append(total_errors)
            # Criterio de parada temprana si el error es cero
            if total_errors == 0:
                self.converged_epoch = epoch + 1
                if self.verbose:
                    print(f"Convergencia alcanzada en la época {epoch + 1}")
                break
        else:
            if self.verbose:
                print(f"No convergió en {self.epochs} épocas (errores en la última época: {total_errors})")
        return self

## Objetivos
1. Comprender la arquitectura matemática interna de una neurona artificial (Perceptrón de Rosenblatt).
2. Implementar el algoritmo de entrenamiento usando únicamente álgebra vectorial (NumPy), sin scikit-learn ni otros frameworks de IA.
3. Simular y evaluar el Perceptrón en las compuertas lógicas **AND**, **OR** y **XOR**.

## Fundamento teórico
La neurona calcula una combinación lineal de las entradas más un sesgo y la pasa por la función escalón:

$$z = \mathbf{w}^T\mathbf{x} + b, \qquad \hat{y} = f(z) = \begin{cases}1 & z \ge 0\\ 0 & z < 0\end{cases}$$

Cuando se equivoca ($e = y - \hat{y} \neq 0$), corrige sus parámetros:

$$w_j \leftarrow w_j + \eta\, e\, x_j, \qquad b \leftarrow b + \eta\, e$$

donde $\eta \in (0, 1]$ es la tasa de aprendizaje.

class Perceptron:
    def __init__(self, input_size, learning_rate=0.1, epochs=100, random_init=False, seed=None, verbose=True):
        self.lr = learning_rate
        self.epochs = epochs
        self.verbose = verbose
        # Inicialización de pesos y sesgo: ceros (por defecto) o valores aleatorios pequeños
        if random_init:
            rng = np.random.default_rng(seed)
            self.weights = rng.uniform(-0.5, 0.5, input_size)
            self.bias = float(rng.uniform(-0.5, 0.5))
        else:
            self.weights = np.zeros(input_size)
            self.bias = 0.0
        self.errors_history = []
        self.converged_epoch = None

    def activation_function(self, z):
        # Función escalón de Heaviside (acepta escalares o vectores)
        return np.where(z >= 0, 1, 0)

    def net_input(self, X):
        return np.dot(X, self.weights) + self.bias

    def predict(self, X):
        """Predice una muestra (vector) o varias a la vez (matriz)."""
        return self.activation_function(self.net_input(X))

    def fit(self, X, y):
        """Entrena el perceptrón actualizando pesos y bias según la regla de aprendizaje."""
        X = np.asarray(X, dtype=float)
        y = np.asarray(y)
        for epoch in range(self.epochs):
            total_errors = 0
            for xi, target in zip(X, y):
                prediction = self.predict(xi)
                error = target - prediction
                # Actualización de pesos y sesgo
                if error != 0:
                    self.weights += self.lr * error * xi
                    self.bias += self.lr * error
                    total_errors += 1
            self.errors_history.append(total_errors)
            # Criterio de parada temprana si el error es cero
            if total_errors == 0:
                self.converged_epoch = epoch + 1
                if self.verbose:
                    print(f"Convergencia alcanzada en la época {epoch + 1}")
                break
        else:
            if self.verbose:
                print(f"No convergió en {self.epochs} épocas (errores en la última época: {total_errors})")
        return self
**Notas de implementación**
- `activation_function` usa `np.where`, así `predict` funciona tanto con una muestra como con toda la matriz $X$ de una sola vez (vectorizado).
- El bucle `for ... else` informa cuando se agotan las épocas sin converger (caso XOR).
- Se guarda `converged_epoch` para poder comparar tasas de aprendizaje sin leer los mensajes impresos.

def graficar(modelo, y, titulo):
    fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(12, 4.5))

    # 1) Convergencia
    epocas = np.arange(1, len(modelo.errors_history) + 1)
    ax1.plot(epocas, modelo.errors_history, marker="o", markersize=3, color="tab:blue")
    ax1.set_title(f"Convergencia — {titulo}")
    ax1.set_xlabel("Época")
    ax1.set_ylabel("Número de errores")
    ax1.set_yticks(range(0, len(y) + 1))
    ax1.xaxis.set_major_locator(plt.MaxNLocator(integer=True))
    ax1.grid(alpha=0.3)

    # 2) Frontera de decisión
    xx, yy = np.meshgrid(np.linspace(-0.5, 1.5, 300), np.linspace(-0.5, 1.5, 300))
    Z = modelo.predict(np.c_[xx.ravel(), yy.ravel()]).reshape(xx.shape)
    ax2.contourf(xx, yy, Z, levels=[-0.5, 0.5, 1.5], colors=["#f4c7c3", "#c6e2c6"], alpha=0.6)

    w1, w2 = modelo.weights
    b = modelo.bias
    x1 = np.linspace(-0.5, 1.5, 100)
    if abs(w2) > 1e-12:
        ax2.plot(x1, -(w1 * x1 + b) / w2, "k--", lw=2, label="Frontera: $w_1x_1+w_2x_2+b=0$")
    elif abs(w1) > 1e-12:
        ax2.axvline(-b / w1, color="k", ls="--", lw=2, label="Frontera (vertical)")

    for clase, color, marca in [(0, "tab:red", "o"), (1, "tab:green", "s")]:
        m = y == clase
        ax2.scatter(X[m, 0], X[m, 1], c=color, marker=marca, s=160, edgecolors="k", zorder=3, label=f"Clase {clase}")

    ax2.set_xlim(-0.5, 1.5)
    ax2.set_ylim(-0.5, 1.5)
    ax2.set_title(f"Frontera de decisión — {titulo}")
    ax2.set_xlabel("$x_1$")
    ax2.set_ylabel("$x_2$")
    ax2.legend(loc="upper right", fontsize=8)
    ax2.grid(alpha=0.3)
    plt.tight_layout()
    plt.show()

Resultado llamativo: **con pesos iniciales en cero, las épocas no dependen de $\eta$**; los pesos finales con $\eta = 0.5$ son exactamente 50 veces los de $\eta = 0.01$.

La razón es matemática: si se parte de $\mathbf{w}=0,\ b=0$, cada actualización suma $\eta \cdot e \cdot \mathbf{x}$, así que en todo momento $\mathbf{w}$ y $b$ son $\eta$ multiplicado por un mismo vector entero. Como la activación solo mira el **signo** de $z = \eta(\ldots)$, multiplicar por $\eta > 0$ no cambia ninguna predicción: la frontera es la misma recta, solo "escalada".

(Con $\eta = 0.1$ AND converge en 4 épocas en vez de 6. No es un efecto real de $\eta$: $0.1$ no se representa exactamente en binario y el redondeo desempata un caso con $z = 0$ exacto. Los valores $0.01$ y $0.5$ dan el resultado "teórico".)

Para ver el efecto real de $\eta$ hay que partir de **pesos aleatorios pequeños**, porque ahí el tamaño del paso sí importa frente a los pesos iniciales:

**Respuesta:**
- Con pesos iniciales en cero y $\eta = 0.1$, el Perceptrón convergió en **4 épocas para AND** y **4 épocas para OR** (con $\eta=0.01$ o $0.5$: 6 para AND y 4 para OR).
- **Efecto de $\eta$:**
  - Con pesos en cero, $\eta$ **no cambia** el número de épocas; solo escala los pesos finales.
  - Con pesos aleatorios, $\eta = 0.01$ es **mucho más lento** (decenas de épocas en promedio) que $\eta = 0.5$ (unas pocas). Con pasos tan pequeños se necesitan muchas correcciones para "vencer" la posición inicial de la recta.
  - Un $\eta$ grande converge rápido en problemas linealmente separables como estos. Para el Perceptrón simple no hay riesgo de divergencia, porque el **teorema de convergencia del Perceptrón** garantiza que termina en un número finito de pasos si los datos son separables. En datos ruidosos, un $\eta$ grande puede hacer que la frontera "salte" más entre épocas.

**¿Qué sucedió?** El Perceptrón **nunca converge** con XOR: aunque se entrene 1000 épocas, cada época comete errores y los pesos entran en un ciclo (se repiten las mismas correcciones una y otra vez). La mejor exactitud posible con una sola recta es 3 de 4 (75 %), y el Perceptrón ni siquiera se queda ahí: con los pesos finales acierta solo 2 de 4 (50 %), porque sigue corrigiendo sin parar.

**Explicación geométrica.** La frontera de decisión del Perceptrón es siempre una **recta** $w_1x_1 + w_2x_2 + b = 0$. En XOR los puntos de clase 1, $(0,1)$ y $(1,0)$, están en una diagonal y los de clase 0, $(0,0)$ y $(1,1)$, en la otra: forman las esquinas cruzadas de un cuadrado. Cualquier recta que deje $(0,1)$ y $(1,0)$ del mismo lado deja también de ese lado al menos uno de los otros dos. No existe ninguna recta que los separe: **XOR no es linealmente separable**. En la gráfica se ve que la recta final siempre deja puntos del color equivocado en su región.

**Demostración algebraica.** Si existiera una recta que separe, debería cumplirse:

| Entrada | Condición |
|---|---|
| $(0,0)\to 0$ | $b < 0$ |
| $(0,1)\to 1$ | $w_2 + b \ge 0$ |
| $(1,0)\to 1$ | $w_1 + b \ge 0$ |
| $(1,1)\to 0$ | $w_1 + w_2 + b < 0$ |

Sumando la 2.ª y la 3.ª: $w_1 + w_2 + 2b \ge 0 \Rightarrow w_1 + w_2 + b \ge -b > 0$ (porque $b<0$), lo que contradice la 4.ª. **No hay solución.**

Esta es la limitación que Minsky y Papert señalaron en *Perceptrons* (1969). La solución es usar **más de una capa** (un Perceptrón multicapa): por ejemplo, $\text{XOR} = \text{AND}(\text{OR}(x_1,x_2),\ \text{NAND}(x_1,x_2))$, donde cada compuerta sí es lineal. Otra opción es transformar las entradas (agregar $x_1x_2$ como tercera variable).

**Valores finales** (con $\eta = 0.1$ y pesos iniciales en cero): $w_1 = 0.2$, $w_2 = 0.1$, $b = -0.2$.

**Significado físico:**
- **Pesos $w_1, w_2$ (importancia de cada entrada):** cada peso dice cuánto "empuja" esa entrada a la neurona hacia activarse. Ambos son positivos, así que un 1 en cualquier entrada acerca la salida a 1. Que $w_1 > w_2$ no significa que $x_1$ sea "más importante" en AND. Es un efecto del orden en que se presentaron las muestras, y con otra inicialización puede salir al revés.
- **Sesgo $b$ (umbral de disparo):** $b = -0.2$ equivale a un umbral $\theta = -b = 0.2$. La neurona es como una balanza: suma la "evidencia" $w_1x_1 + w_2x_2$ y solo se activa si supera el umbral. El sesgo negativo la deja "apagada por defecto".
- **Decisión:** solo $x_2$ activa da $0.1 < 0.2$ y no se dispara. Ambas activas dan $0.3 > 0.2$ y sí se dispara. Esa es la lógica AND: *"se necesitan las dos entradas"*.
- **Detalle importante:** para $(1,0)$ la suma es $0.2 - 0.2 = 0$ exactamente; ese punto queda **sobre** la frontera. En aritmética exacta se clasificaría como 1 (porque $z \ge 0$). Si da 0 es solo porque $0.1$ no se representa exacto en binario y $z$ queda en $\approx -2.8\times10^{-17}$. Eso muestra que el Perceptrón se detiene apenas deja de cometer errores y **no busca margen**: la recta puede quedar pegada a los puntos. Con $\eta = 0.5$ la solución es $w = [1, 0.5],\ b = -1.5$ (umbral 1.5), con el mismo comportamiento lógico.
- **Geometría:** $(w_1, w_2)$ es el vector normal a la frontera (apunta hacia la región de clase 1) y $b$ desplaza la recta alejándola del origen. Para OR, en cambio, $w = [0.1, 0.1],\ b = -0.1$: el umbral es igual a un solo peso, así que basta **una** entrada activa para dispararse.

> Nota: $(0.2, 0.1, -0.2)$ no es la única solución. Cualquier múltiplo positivo, u otra recta que separe $(1,1)$ del resto, es igualmente válido. El Perceptrón se detiene en la **primera** solución que encuentra, no en la "mejor" (a diferencia, por ejemplo, de una SVM, que maximiza el margen).
## Conclusiones
1. El Perceptrón implementado solo con NumPy aprende correctamente AND y OR en pocas épocas, porque ambos problemas son **linealmente separables**.
2. Con pesos iniciales en cero, la tasa de aprendizaje solo escala la solución. Con pesos aleatorios, un $\eta$ mayor acelera la convergencia en estos problemas.
3. El Perceptrón simple **no puede** resolver XOR: su frontera es una recta y XOR no es separable por ninguna recta. Superar esta limitación requiere redes multicapa, lo que motivó el desarrollo del *backpropagation*.
